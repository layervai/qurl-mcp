Secure MCP Gateway

qURL Connector

A secure Streamable HTTP MCP gateway for accessing qURL-protected MCP servers. Codex uses a normal MCP endpoint; the connector obtains qURL authorization, opens the protected resource, and forwards authorized MCP traffic without exposing qURL credentials to the client.

Standard MCPSecure AccessProtected ServicesCRID Routing
Gateway role: qURL Connector is the security access layer in front of protected MCP servers. It accepts standard MCP requests from Codex, uses the configured CRID to obtain and validate qURL authorization, establishes the portal to the protected resource, and proxies only authorized MCP and SSE traffic. The client never connects directly to the protected MCP server and never receives the temporary qURL link, portal credentials, or gateway-held authorization state.

Design Objectives

Client Compatibility

Transparent Codex integration

Codex connects through a single standard MCP URL. No qURL link or portal credential is configured on the client.

Authorization Boundary

Credentials remain at the gateway

qURL credential links, portal state, and qurl_vsession cookies stay inside the connector.

Session Scope

One authorization per session

A new MCP session performs Share and EnterPortal once. Calls and SSE reconnects reuse it.

Service Isolation

One CRID per MCP service

Each Codex MCP configuration sends its assigned CRID. The connector binds that CRID to the returned MCP session ID.

Topology

The service-to-CRID mapping is supplied offline. Its lack of a connection line is intentional: it informs client configuration but is not part of the runtime path.

Session Sequence

An SSE connection remains open for its stream lifetime. Regular MCP calls are independent HTTP requests, but reuse the gateway-held portal authorization rather than creating a new qURL link.

Initialization Flow

  1. 1
    Select the service CRIDThe Codex configuration supplies the CRID assigned to the target MCP service.
  2. 2
    Create the portalThe gateway calls Share(CRID), validates the resulting link, and opens its portal.
  3. 3
    Forward initializationThe MCP service receives the initialize request through the authorized resource URL.
  4. 4
    Register the sessionOn a successful response carrying Mcp-Session-Id, the gateway stores the session mapping.
  5. 5
    Reuse the portalSubsequent POST, SSE GET, and DELETE requests use the session mapping directly.

Offline Step 2

CRID configuration material

Service-to-CRID mapping is delivered offline after resource registration. It does not create a network path between Codex, the gateway, qURL, or the MCP service.

Its sole purpose is to tell the Codex configuration owner which CRID belongs to each MCP service definition.

Do not configure a temporary qURL link in Codex.
Configure the stable gateway URL and service-specific CRID. The gateway owns temporary links and portal state.

Session Lifecycle

Create

New initialize

No session ID: create a portal from the supplied CRID. A successful response registers the service-issued session ID.

Reuse

Calls and SSE reconnects

Look up Mcp-Session-Id and forward through the stored portal. No new share occurs.

Close

DELETE

Forward the request through the existing portal. Delete the local mapping only after a successful 2xx upstream response.

Expire

Timeout or restart

The in-memory registry is actively purged every minute: 15-minute idle TTL and 24-hour absolute TTL. Restarting clears all mappings.

Implementation Status

Implemented in the qURL Connector

The connector maintains an in-process Mcp-Session-Id → portal / ResourceURL / CRID registry. Unknown or expired session IDs return 404 and require MCP re-initialization. A CRID that conflicts with an existing session returns 409.

Because portal handles are process-local, production deployments should use sticky routing for requests belonging to the same MCP session. Cross-instance reuse requires a session layer that can safely recreate or share qURL portal authorization; serializing a portal handle into an ordinary cache is not sufficient.
